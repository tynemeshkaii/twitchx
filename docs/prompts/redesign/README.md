# Редизайн TwitchX — общий контекст для всех фаз

Этот файл читает агент **каждой** фазы перед началом работы. Промпты фаз
(`phase-0-…md` … `phase-4-…md`) ссылаются на него и не повторяют то, что
написано здесь.

## Как запускать

Одна фаза — одна сессия — один PR. Начинай новую сессию с сообщения:

```
Выполни docs/prompts/redesign/phase-N-<name>.md
```

Фазы строго последовательны: фаза N стартует только после того, как PR фазы N-1
смержен в `main`. Каждый промпт начинается с проверки этого условия.

| Фаза | Файл | Оценка |
|---|---|---|
| 0 | `phase-0-prep-and-bugs.md` — превью-харнесс и баги | 1 день |
| 1 | `phase-1-tokens-and-cleanup.md` — токены, чистка эффектов | 2 дня |
| 2 | `phase-2-shell-and-navigation.md` — каркас, навигация, удаление плеер-бара | 4–5 дней |
| 3 | `phase-3-components.md` — компоненты по новому образцу | 4–5 дней |
| 4 | `phase-4-polish-and-release.md` — движение, доступность, QA, доки | 1–2 дня |

## Откуда это взялось (аудит, кратко)

Аудит визуала показал: фундамент хороший (токены и темы разложены по слоям,
проверка владельцев CSS-селекторов, focus-ring, reduced-motion,
high-contrast, свой набор иконок), но интерфейс перегружен:

- **Эффекты включены все сразу:** стекло (`backdrop-filter` 38 раз, в том
  числе поверх непрозрачного фона), свечение акцентом (`--shadow-glow-accent`,
  13 мест), шум, бесконечная анимация фона `#app` (`mesh-drift 24s`),
  градиенты на кнопках, шесть эффектов ховера на карточке.
- **Цвета спорят:** оранжевый акцент, фиолетовый Twitch, неоновый Kick
  `#53FC18`, красный YouTube, зелёный live, красный и голубой. Зелёный значит
  четыре разные вещи. `--warn-yellow` в тёмной теме равен дефолтному акценту.
- **Типографика без шкалы:** 17 разных `font-size`, сырые 8/9/15/17/22/28 px,
  шесть весов (включая 750 и 800), почти всё жирное.
- **Отступы и радиусы без шкалы:** 14 шагов `--space-*`, 127 сырых `padding`,
  радиусы 6/10/14/20 и сырые 1–4/24 px.
- **Дубли в структуре:** фильтр платформ в трёх местах тремя разными
  компонентами, два Refresh, глобальный плеер-бар виден всегда, Browse
  спрятан внизу сайдбара, мультистрим доступен только из контекстного меню,
  аккаунты занимают верх сайдбара.

**Направление:** «тихий интерфейс, громкий контент». Нейтральный графит как
в нативных macOS-приложениях (ориентиры Apple TV, Music, Arc, Linear), один
акцент только для выделения, фокуса и главной кнопки, цвет на экране несут
превью и аватарки. Платформы обозначаются маленькими точками и глифами,
никогда заливкой кнопки. Одна функция живёт в одном месте.

## Принятые решения

Пользователь согласился с рекомендациями. Если в задаче сессии сказано иначе,
приоритет у задачи.

| Вопрос | Решение | Фаза |
|---|---|---|
| Клик по карточке/строке | Одиночный клик **сразу запускает** стрим. Состояние выбора остаётся только для клавиатуры (Space = watch, ←/→ = next/prev stream). | 2 |
| Режимы плотности сетки | Два: `grid` и `list`. Сохранённые `comfortable`/`compact` мигрируют в `grid`. | 3 |
| Акцент по умолчанию | Оранжевый остаётся. Предупреждения получают свой жёлтый. | 0–1 |
| Mini mode | Остаётся, кнопка переезжает в поповер аккаунта + хоткей. | 2 |
| Настройки | Модалка в стиле окна настроек macOS внутри того же WebView, не отдельное окно. | 3 |

## Правила для всех фаз

1. **Прочитай `CLAUDE.md` целиком.** Его правила в силе: JS-модули по
   шаблону с `const TwitchX = window.TwitchX;` (никогда `var`), top-level имена
   уникальны во всём бандле, никакого `style.display` (только
   `classList.toggle('hidden')`), никакого `innerHTML` с данными, AppKit
   только через `AppHelper.callAfter`, YouTube ID не `.lower()`.
2. **Имена существующих токенов не переименовывать.** `tests/test_contrast.py`
   и `tests/test_overlay_contrast.py` читают по имени `--text-primary`,
   `--text-secondary`, `--text-muted`, `--bg-base`, `--bg-elevated`,
   `--live-green`, `--error-red`, `--warn-yellow`, `--text-on-accent` и др.
   Меняем значения, новые токены только добавляем.
3. **ID элементов переносить, а не переименовывать.** JS ищет элементы по
   ID. Перед удалением или переименованием любого ID сделай
   `grep -rn "<id>" ui/js ui/api tests` и обнови все ссылки в том же коммите.
4. **Один логический шаг — один коммит.** Сообщение в повелительном
   наклонении на английском, первая строка до 72 символов
   (`Fix collapsing stream thumbnails`).
5. **Гейты перед каждым пушем:**
   - `make check` (ruff + pyright + pytest) зелёный. **На Linux (облачная
     сессия) `make check` не работает:** `uv` пытается собрать
     `pyobjc-framework-*`, а это только macOS. Там используй
     `make check-linux` (появляется в фазе 0, шаг 0.0): ruff + pytest без
     pyobjc, и pyright, у которого допустимы только ошибки
     `reportMissingImports` для `AppKit`, `Foundation`, `PyObjCTools`,
     `objc`, `webview.platforms.cocoa`;
   - `uv run python tools/css_ownership.py` возвращает 0;
   - `make preview` (появляется в фазе 0) без ошибок страницы, скрины
     просмотрены глазами: открой PNG и посмотри, а не просто проверь, что
     файлы есть.
6. **Тесты не покрывают JS и вёрстку.** Поэтому визуальную проверку через
   `make preview` делай после каждого шага, который трогает `ui/`. Chromium не
   равен WKWebView: всё, что зависит от macOS (titlebar, fullscreen, PiP,
   AVKit), помечай в описании PR как «нужна проверка на маке».
7. **Не расширяй объём.** Делай то, что в промпте фазы. Замеченное вне
   объёма — в раздел «Замечено, не сделано» описания PR.
8. **Если `uv` недоступен:** `.venv/bin/python -m pytest tests/ -q`. Если и
   `make check-linux` ещё нет (фаза 0 не смержена), команда для Linux:
   ```bash
   uv run --no-project --python 3.12 --with pytest --with pytest-asyncio \
     --with pytest-httpx --with pytest-cov --with httpx --with curl-cffi \
     --with "pillow<12" --with "websockets>=16" --with "pywebview>=5,<6" \
     python -m pytest tests/ -q -p no:cacheprovider
   ```
9. **`docs/**` в `.gitignore`.** Новые файлы в `docs/` (например
   `docs/screenshots/` в фазе 4) добавляй через `git add -f`.

## Ветки и PR

- Работай в ветке, которую назначила сессия. Если её нет, создай
  `redesign/phase-N` от свежего `origin/main`.
- В конце фазы запушь ветку и открой PR в `main` с заголовком
  `Redesign phase N: <тема>`. Описание PR:
  - что сделано, по шагам промпта (номера шагов);
  - результаты гейтов;
  - список скринов из `.preview/`, которые стоит сравнить, и что на них
    изменилось;
  - «Нужна проверка на маке» — конкретный чек-лист;
  - «Замечено, не сделано».
- Не мержи PR сам.
